\section{Introduction}
Sale prices of apartments, houses and land plots in Azerbaijan vary over
several orders of magnitude, and a model that estimates a fair price from a
listing's location, size and condition is useful to buyers and sellers. We use
a public bina.az scrape and study two tasks: predicting the price (Task~A) and
predicting whether a listing is above the median training price (Task~B).
The aim of the project is not a new model but a careful, reproducible
comparison of two classic learners that we implement ourselves.

Our contributions are: (i)~a NumPy decision tree for classification and
regression and a NumPy Pegasos SVM with random Fourier features, both tested
against scikit-learn; (ii)~a leakage-aware data pipeline with a fixed split
and a single test evaluation; (iii)~a benchmark with matched scikit-learn
baselines, 5-fold cross-validation and timing; (iv)~an error analysis
that shows where the models fail; and (v)~several bonus models built on
the same code. One command, \texttt{python -m src.run\_all}, regenerates
every number, table and figure; results are deterministic for seed~42.

\section{Related Work / Background}
Classification and regression trees recursively partition the feature
space using threshold rules. At each node, the split is selected to reduce
task-specific impurity: Gini impurity or entropy for classification and
mean-squared error for regression~\cite{breiman1984}. This produces
interpretable piecewise-constant predictions, while tree depth and minimum
leaf size control the bias--variance trade-off. Our NumPy implementation
uses these criteria for the binary price-tier and continuous price tasks.

Support-vector machines separate classes with a maximum-margin boundary;
the soft-margin formulation trades margin width against hinge-loss
violations~\cite{cortes1995}. Pegasos optimizes the primal objective with
stochastic sub-gradient updates and a learning rate inversely proportional
to iteration and regularization strength~\cite{pegasos}. For non-linear
decision boundaries, random Fourier features approximate the RBF kernel
with an explicit finite-dimensional mapping~\cite{rahimi2007}.

\section{Data and Preprocessing}
We use the Kaggle \emph{binaaz-sale-project} dataset, whose supplied CSV
contains 100,775 scraped rows and 51 columns; prices are in AZN. The rows
describe only 64,454 distinct listings, because a listing is scraped several
times. We keep the most recently scraped row of each listing. Left in, the
same listing appeared in both train and test and inflated the test score.
Plausibility filters then remove 104 rows with prices outside
$[5{,}000;\,20{,}000{,}000]$ AZN or areas outside $[8;\,10^6]$~m$^2$ (typos
such as an 11~AZN flat), leaving \textbf{64,350 listings}. Valid expensive
listings are kept rather than capped. Areas given in \emph{sot} are converted
to m$^2$; floor and building floors are parsed from the floor field. Missing
numeric values are imputed with training medians and missing categories become
\texttt{Unknown} before one-hot encoding, giving 171 features.

We exclude identifiers, URLs, free text, scrape timestamps, view counts and
currency labels. \texttt{unit\_price} and \texttt{total\_price} are removed as
well: they are derived from the target and would leak it into both tasks.
For Task~B a listing is premium (1) only when its price is strictly above the
\emph{training} median (210,000~AZN); ties are standard (0), and the same
threshold labels validation and test rows. The seed-42 split is stratified by
tier: 70\% train, 15\% validation and 15\% test (45,045, 9,652 and 9,653
listings). Standardisation is fitted on training rows only.

\section{Method}
\subsection{Decision tree (from scratch)}
A node splits samples with $x_j\le\tau$ to the left. The impurity is Gini
$1-\sum_k p_k^2$, entropy $-\sum_k p_k\log p_k$, or, for regression, the
variance of the targets (MSE). For each feature we sort the values once and
evaluate every midpoint between consecutive distinct values using cumulative
class counts (or cumulative sums and sums of squares for regression), so a
split search costs $O(n\log n)$ per feature. The split with the largest
weighted impurity decrease
$\frac{n}{N}\bigl(I(\text{parent})-\frac{n_L}{n}I(\text{left})-\frac{n_R}{n}I(\text{right})\bigr)$
is taken. Growth is recursive and stops on \texttt{max\_depth},
\texttt{min\_samples\_split}, \texttt{min\_samples\_leaf} or
\texttt{min\_impurity\_decrease}. A leaf predicts the class counts
(normalised for \texttt{predict\_proba}) or the mean target. Feature
importances are the summed impurity decreases. The same class also supports
random feature subsets (\texttt{max\_features}), which the forest bonus uses.

\subsection{Support-vector machine (from scratch)}
For the binary price-tier task, the two original class labels are mapped
deterministically to $\{-1,+1\}$ during fitting. Predictions are mapped
back to the original labels before evaluation. Our NumPy implementation
minimises the soft-margin primal objective
\begin{equation}
  J(\mathbf{w},b)=
  \frac{\lambda}{2}\lVert\mathbf{w}\rVert_2^2+
  \frac{1}{n}\sum_{i=1}^{n}
  \max\!\left(0,1-y_i(\mathbf{w}^{\top}\mathbf{x}_i+b)\right).
\end{equation}
Training uses a single-sample, Pegasos-style stochastic subgradient variant,
without a projection step. At iteration $t$, one training example is sampled
using a fixed random seed and the learning rate is
$\eta_t=1/(\lambda t)$.
The weight vector is always shrunk by $1-\eta_t\lambda$. If the sampled
margin $y_i(\mathbf{w}^{\top}\mathbf{x}_i+b)$ is below one, the update is
\begin{align}
  \mathbf{w} &\leftarrow
  (1-\eta_t\lambda)\mathbf{w}+\eta_t y_i\mathbf{x}_i,\\
  b &\leftarrow b+\eta_t y_i.
\end{align}
Otherwise only the shrinkage is applied. The bias is not regularised, and
inputs must be standardised. The decision function is
$f(\mathbf{x})=\mathbf{w}^{\top}\mathbf{x}+b$; samples with
$y_i f(\mathbf{x}_i)\leq 1$ are reported as margin-violating, and the
geometric margin width is $2/\lVert\mathbf{w}\rVert_2$.

For a non-linear extension we approximate the RBF kernel with random
Fourier features~\cite{rahimi2007}:
\begin{equation}
  \phi(\mathbf{x})=
  \sqrt{\tfrac{2}{D}}
  \bigl[\cos(\boldsymbol{\omega}_1^{\top}\mathbf{x}+b_1),\ldots,
  \cos(\boldsymbol{\omega}_D^{\top}\mathbf{x}+b_D)\bigr],
\end{equation}
with $\boldsymbol{\omega}_j\sim\mathcal{N}(\mathbf{0},2\gamma\mathbf{I})$ and
$b_j\sim\mathcal{U}[0,2\pi]$. The map is drawn once, fitted on the
training data, and reused unchanged for validation and test. Linear Pegasos is
then trained in the transformed space. $D$ trades approximation quality
against cost; $\gamma$ sets the locality of the approximated kernel.

\section{Experimental Setup}
\paragraph{Metrics.} Task~A: RMSE, MAE and $R^2$ in AZN, plus RMSE and $R^2$
on $\log$ price, because prices are heavy-tailed. Task~B: accuracy,
precision, recall, F1, ROC-AUC and PR-AUC. All metrics are NumPy
implementations in \texttt{src/evaluate.py}.

\paragraph{Protocol.} Every hyperparameter is chosen on the validation split.
The test split is scored exactly once, after the final configurations are
fixed. Cross-validation (5 folds; stratified by tier for Task~B) uses only
train+validation rows, with scaling fitted inside each fold. The seed is 42
throughout. The tree search covers depths
$\{1,2,3,4,5,6,8,10,12,15,\text{none}\}$ and minimum leaf sizes
$\{1,2,5,10,20,50,100,200\}$; for Task~B Gini and entropy are compared, each
at its own best setting.

\paragraph{SVM protocol.}
The linear search uses
$\lambda\in\{10^{-5},10^{-4},10^{-3},10^{-2},10^{-1},1\}$. The RFF search is
a \emph{joint} grid over
$\lambda\in\{10^{-5},3\cdot10^{-5},10^{-4},3\cdot10^{-4}\}$ and
$\gamma\in\{0.003,0.01,0.03,0.1\}$, because the best $\lambda$ for the linear
model need not suit the feature map. Validation F1 selects the model; ties
prefer stronger regularisation, and linear wins a tie between families. The
full run uses $D=1024$ components and $400{,}000$ single-example updates per
candidate, about 8.9 passes over the 45,045 training rows. The
\texttt{--fast} configuration is only for development.

\paragraph{Baselines.} Each scikit-learn model minimises the same objective as
ours (\texttt{src/baselines.py}). Trees use the same criterion, depth and leaf
settings. For the linear SVC, $C=1/(\lambda n)$ makes its objective a
rescaling of ours. \texttt{SGDClassifier} (hinge) uses $\alpha=\lambda$, and
\texttt{RBFSampler}+SGD is the matched pipeline for RFF. Because the exact
kernel SVC is $O(n^2)$, we compare with linear SVC. Fit times are wall-clock
means per CV fold on one laptop and should be read as ratios, not absolutes.

\subsection{Results A: decision tree}
Validation selects depth 8 and a minimum leaf size of 10 for Task~A (125
leaves). Test RMSE is 358,672~AZN ($R^2=0.661$) against 358,999 for
scikit-learn's tree. An unlimited-depth tree memorises the training data
(train RMSE 3,951 vs.\ validation RMSE 535,870), so depth acts as the main
regulariser. The 5-fold CV RMSE is $438{,}746\pm29{,}122$: higher than the
single test RMSE and with a wide spread, which shows that RMSE is dominated by a
few very expensive listings and depends on which of them fall in a split.
For Task~B, entropy and Gini differ by only 0.0011 validation F1
(Table~\ref{tab:tree_criteria}), so we use entropy with an unlimited depth. The
final tree has 3,068 leaves and test F1 0.919. With matched settings, ours
and scikit-learn's classification trees have 3,068 and 3,079 leaves and agree
on 97.9\% of test predictions; the regression trees both have 125 leaves but
agree on 87.5\% of predictions, so the two implementations are close in
accuracy but not identical (we did not trace the difference, which may come
from tie-breaking).

\subsection{Results B: SVM}
Validation selects RFF with $D=1024$, $\gamma=0.01$ and
$\lambda=3\cdot10^{-5}$. Validation F1 is 0.845, test F1 is 0.838 and test
ROC-AUC is 0.924. The final objective is 0.424, the weight norm is 39.6, the
RFF-space margin width is 0.0505, and 17,528 training examples lie on or
inside the functional margin. In 5-fold cross-validation our SVM obtains F1 $0.843\pm0.005$, the same as
scikit-learn's linear SVC ($0.843\pm0.008$), while fitting in 5.3~s instead of
245.4~s per fold (about 46 times faster; Table~\ref{tab:results_task_b} lists
6.4~s against 303.2~s for one fit on the full training split). The two solve
different feature-space problems (RFF versus a linear kernel), so this is not a
like-for-like solver comparison. On validation, the best RFF model beat the best
purely linear Pegasos model ($\lambda=0.01$) by 0.845 to 0.840 F1, a small
gain. The objective (Fig.~\ref{fig:svmconv}) is noisy early because of the
large initial step sizes and settles near 0.4 after about $10^5$ updates.

\subsection{Bonus models}
All bonus models are our NumPy code; scikit-learn is used only for comparison
(Table~\ref{tab:bonus}). A from-scratch ridge regression and $\varepsilon$-SVR
reach RMSE of about 583k~AZN, far worse than the tree (359k), so Task~A is
strongly non-linear. A random forest of 30 of our trees improves Task~B F1 to
0.936 (scikit-learn: 0.936) and Task~A RMSE to 318,706 (scikit-learn:
343,257); the forest settings are matched only in part, so we do not claim
that ours is the better implementation. AdaBoost (depth-3 trees, 100 rounds,
weighted bootstrap) reaches F1 0.904 (scikit-learn: 0.900). For clustering,
the first 20 principal components explain only 22.1\% of the variance, and
K-means ($k=4$) and DBSCAN ($\varepsilon=1$~km) have adjusted Rand index
of at most 0.072 against price tier and region, i.e.\ geography
alone does not recover price tiers.

\section{Discussion and Limitations}
\paragraph{Tree versus SVM.} The tree wins on F1 (0.919 vs.\ 0.838) although
the SVM has the higher ROC-AUC (0.924 vs.\ 0.920) and PR-AUC (0.923 vs.\
0.884). The SVM's precision (0.768) is far below its recall (0.922), i.e.\ it
labels too many listings premium at its default threshold. We hypothesise that
a tuned threshold would close much of the F1 gap, but we did not test this.

\paragraph{Where the models fail.}
Table~\ref{tab:errors} shows the test error of the tree by true-price band.
Cheap listings are over-predicted (mean signed error $+29{,}928$~AZN), and the
top 1\% (99 listings) are badly under-predicted ($-1.48$M~AZN on average, MAE
2.31M): a leaf averages over its training listings and cannot reach
extreme prices. Districts with fewer than 200 training rows have a median
relative error of 0.355, against 0.177 for well-represented districts.

\paragraph{Limitations.}
The data are asking prices from a scrape, not transaction prices, and about
700 rows may be re-posted near-duplicates that we did not remove, which can
slightly favour matches between train and test. Cleaning limits on price and
area were fixed from the distribution, not tuned. The SVM has no projection
step and no calibrated probabilities, and uses a finite-dimensional
approximation of the RBF kernel. Fit times depend on the machine and the
implementation; our pure-NumPy tree is about 5 to 30 times slower than
scikit-learn's compiled one (CV fit 4.5~s vs.\ 1.0~s for Task~A, 20.5~s vs.\ 0.7~s for Task~B). AdaBoost's weighted bootstrap adds sampling
variability. Results come from one seed and one split; the CV spread
($\pm29{,}122$ RMSE) shows that single-split RMSE differences below that size
should not be over-interpreted.

\section{Conclusion}
Tree models trained from scratch match scikit-learn to within 0.001 F1 and
0.1\% RMSE, and our Pegasos+RFF SVM matches a linear SVC in F1 and fits about 46 times faster. On this data the tree is clearly the better classifier by F1,
and bagging it into a forest helps further. Next steps are tuning the SVM
decision threshold, modelling log price to reduce the luxury-listing error,
and de-duplicating re-posted listings.
